# Atlas Studio for AI assistants (MCP server, private, local)

Part of Atlas Studio, the planner toolkit (Ryan, 2026-11-17). A read-only MCP server that lets Claude on this Mac answer planner questions from Atlas's own data (CIV-1650). It runs over stdio and reads published data straight from the cloud: the release the map reads, its Atlas Studio MCP files, read only with no key (CIV-2014). Since CIV-2914 it is `atlas-studio-dev`, for testing MCP code before it deploys, so it reads exactly what the hosted server reads and answers the same; nothing on this Mac except the opt-in test folders below. It uploads and writes nothing, and is not deployed anywhere.

## Setup

For Atlas's own development and test rounds on this Mac only. Testers and everyone else use the hosted server through their private link (`workers/atlas-mcp`); Ryan, 2026-11-22: "I don't want people downloading MCP atlas though i only want them using the hosted version". The commands that register the local server with Claude Code, Claude Desktop and Antigravity are kept on this Mac, outside git, in `_reports/mcp-server/LOCAL-SETUP.md`.

## Tools

| Tool | Answers |
|---|---|
| `list_agencies` | Which agencies it covers, filtered by name or city, region and country, or near a place (40 rows at most) |
| `rank_agencies` | Agencies ranked by routes every N minutes or better in a period, filtered by country, region and size (or "similar to" an agency) |
| `route_frequency` | A route's frequency in each period on a day type, with first and last trips and its branches; with a time window, hour by hour for each branch |
| `routes_at_frequency` | An agency's routes that run every N minutes or better in a period |
| `compare_agencies` | For several agencies, how many routes run every N minutes or better in a period |
| `routes_near` | Routes that stop near a corner, station or stop, with the stops they use there |
| `route_history` | How a route's frequency changed over the years, from Atlas's History data |
| `buses_needed` | Buses needed for a route in a period, from Studio's buses-needed file (now, and every 10/15/20/30/60) |
| `trip_time` | Scheduled trip time between two stops, per route, by the hour the trip leaves |
| `combined_frequency` | Every route between two stops, and how often a trip leaves on any of them combined |
| `explain_method` | Atlas's own explanation of a method or term, word for word from the Docs page (generated by `docsMethodsRender.ts`; `docsMethods.test.ts` fails when the page changes) |
| `schedule_changes` | Frequency changes between two schedules, where Studio has built the comparison |

`waitMinutes` in the frequency tools is the typical wait on the route's slower direction: its main stretch plus its steady branches, the number the map colours and filters the route by. A branch end that runs unevenly shows only in `shown`, the route list's own words. A range like "every 5–16 min" means every 5 on the busiest part of the route and every 16 on the quietest.

The test questions, which any chat adds to: [QUESTIONS.md](QUESTIONS.md). Every round's results: [TEST-LOG.md](TEST-LOG.md). Rerun them after every change to the server. Questions the pilot's testers got wrong answers to join QUESTIONS.md weekly, from the review sheet `weeklyReview.ts` writes (CIV-1853).

## Data

The tools read through one async store (`shared/mcpStore.ts`). This local server reads the published release's split files (`shared/mcpSplitStore.ts`, the files the hosted server reads), found through the release pointer the map reads (`shared/mcpRelease.ts`, re-read at most once a minute; `scripts/mcp/currentRelease.ts`). The Live tools read the private Live bucket with the read-only keys (`local-api/privateBucket.ts`), as the hosted server reads its `MCP_LIVE` binding. When the cloud can't be reached, a tool says Atlas couldn't answer; there is no copy on this Mac to fall back on. Tests also use an in-memory store, and a test checks that every store gives equal answers.

- **Opt-in test folders only.** `ATLAS_MCP_STORE=split:<folder>` (split release files), `ATLAS_MCP_DATA_DIR` (route files), `ATLAS_MCP_LIVE_DIR` (Live files laid out like the private bucket) and `ATLAS_MCP_FEEDS_DIR` (below) read disk, for tests.
- **Frequencies.** Each agency's published route data. Every number comes from the map's own functions: `routeListFilterDisplay`, `routeListDisplay`, `routeRuns` and the hourly chart values.
- **Trip times and combined frequency.** Only when `ATLAS_MCP_FEEDS_DIR` is set (CIV-2914: the hosted server has no schedule files, so by default these tools and stop_frequency's every-route reading are off here too). They read the schedule files in that folder (`<slug>/` and any `<slug>--supplemental-N/`, newest of each). With `also_agencies`, other agencies count together; a place named on one agency is found on another by stops within a 500 m walk (`SAME_PLACE_METRES`). It is read the way processing reads it (`pipeline/stopToStop.ts`): same week, same services, near-duplicate trips dropped, same representative weekday. Trip times are summarized with the running-time rules (`runningTimeSummary`). Combined frequency uses the stop-pool rule the map uses at a stop (`pooledReadingInWindow`).
- **Agency index.** `rank_agencies` reads the release's ranking lists.
- **History.** `route_history` reads Atlas's published History data from the release, with History's own snapshot rules.
- **Buses needed.** `buses_needed` reads Studio's buses-needed file from the release (the cloud rebuild makes it). It never runs the calculation, which takes minutes on a large agency. Where an agency has no file, it says so. Targets are the public scale only (10, 15, 20, 30, 60), with the schedule's own layover.
- **Testing.** The MCP chat runs the questions in [QUESTIONS.md](QUESTIONS.md) itself in fresh headless chats and logs the results in [TEST-LOG.md](TEST-LOG.md).
- **Public agencies only.** It answers only for agencies in `public/data/catalog-public.json`.
- **Schedule changes.** These come from Studio's comparison files in the release, ranked by the shared rule (`shared/frequencyChange.ts`).
